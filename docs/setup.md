# 段階 0 の本人作業

完了条件は「Mac でログインし、Drive にフォルダを作れる」。所要は 30 分ほど。
このリポジトリの作業はテスト用 Vault だけを使う。普段の Vault は開かない。

## 1. Google Cloud（設計書 4.2）

1. [Google Cloud コンソール](https://console.cloud.google.com/) で個人用のプロジェクトを作る。
2. 「API とサービス」のライブラリで **Google Drive API** を有効にする。
3. OAuth 同意画面（Google Auth Platform）を設定する。
   - 対象は **外部**。
   - データアクセスに追加する権限は `https://www.googleapis.com/auth/drive.file` **だけ**。
4. クライアントを作る。種類は **デスクトップ アプリ**。
5. ホームページとプライバシーポリシーを公開し、ブランディングに登録する（下の「公開用のページ」）。
   これが空だと「アプリを公開」が止まる（2026-11-05 に実際に発生）。
   その後、公開ステータスを **本番** にする。「テスト」のままだとトークンが 7 日で失効する。審査は申請しない。
6. 表示されたクライアント ID を控える。シークレットも、1Password などに控える。
   どちらもリポジトリにも Vault にも置かない。

### 公開用のページ

`site/` の 3 ファイルを GitHub Pages で公開する。プラグイン本体とは別の公開リポジトリにすれば、本体は非公開のままにできる。

1. GitHub で公開リポジトリ `vault-sync-site` を作る。
2. 「Add file」の「Upload files」で `site/` の中の 3 ファイルをリポジトリ直下に入れる。`site` フォルダごとは入れない。
3. リポジトリの Settings の Pages で、Source を「Deploy from a branch」、Branch を `main` の `/ (root)` にして保存する。
4. `https://<GitHub 名>.github.io/vault-sync-site/` が開くことを確かめる。

Google Cloud のブランディングに次を入れて保存する。

| 項目 | 値 |
|---|---|
| アプリケーションのホームページ | `https://<GitHub 名>.github.io/vault-sync-site/` |
| プライバシー ポリシーのリンク | `https://<GitHub 名>.github.io/vault-sync-site/privacy.html` |
| 利用規約のリンク | 空のまま |
| 承認済みドメイン | `<GitHub 名>.github.io` |

## 2. テスト用 Vault でログインする

ビルドとテスト用 Vault の生成はターミナルで行う。

```bash
cd gdrive-vault-sync
npm install
npm run make-test-vault
npm run dev
```

続きは Obsidian で操作する。

1. 「保管庫を切り替える」→「フォルダを保管庫として開く」で、リポジトリ内の `_test-vault` を開く。
2. 設定 →「コミュニティプラグイン」で制限モードを切り、**GDrive Vault Sync** を有効にする。
3. 設定の GDrive Vault Sync に、クライアント ID とシークレットを入れる。シークレットが空だとログインが完了しない（2026-11-07 に確認）。
4. 「ログイン」を押す。ブラウザで「確認されていないアプリ」の警告が出たら続行し、許可する。
5. 「接続の確認」の「確認」を押す。

マイドライブに `Obsidian/_test-vault/` ができれば完了条件を満たす。

## 3. つまずいたとき

- **ブラウザでは許可できたのに、ログイン済みにならない:** シークレットが空でないか確かめ、もう一度ログインする。
- **マイドライブに `Obsidian` フォルダが 2 つできた:** 想定どおり。`drive.file` はこのアプリが作ったフォルダしか見えない。
  手で作った同名のフォルダとは別物になるので、紛らわしければ「Drive のフォルダ名」を変える。

# 段階 2 の本人作業

完了条件は「テスト用 Vault の全件を Drive と往復でき、MD5 が一致する」。
`npm run dev` は動かしたままにする。普段の Vault は開かない。
コマンドは Obsidian のコマンドパレット（`Cmd+P`）で「GDrive Vault Sync」と入れて選ぶ。

## 1. テスト用 Vault から Drive へ送る

1. `_test-vault` を開いて `Cmd+R` で再読み込みする。
2. **試行（計画を見るだけで、何も書き込まない）** を実行する。アップロードの件数を確かめて閉じる。
3. **同期を実行** を実行する。初回の確認画面で内容を確かめ、「実行」を押す。
4. 完了したら **端末と Drive を照合** を実行する。「端末のみ 0 / Drive のみ 0 / 内容が違う 0」なら送信は成功。

## 2. 空の Vault へ受け取る

`_test-vault-2/_test-vault` は中身が空の 2 台目にあたる。

1. ターミナルの別タブで `npm run make-second-vault` を実行する（プラグインを写す）。
2. Obsidian で `_test-vault-2/_test-vault` を開き、制限モードを切ってプラグインを有効にする。
3. 設定でクライアント ID とシークレットを入れてログインする。Vault ごとに必要。
4. **同期を実行** を実行し、確認画面で「実行」を押す。
5. **端末と Drive を照合** を実行する。すべて 0 なら往復が成功で、完了条件を満たす。

## 3. つまずいたとき

- 途中で失敗したら **ログをコピー** でログを取り、内容を確かめる。ログは Vault に書かない。
- `.obsidian` の中に競合コピーができることがある。2 台目の Obsidian が作る既定の設定と Drive の内容が違うため。段階 2 ではそのままでよい。

# 段階 3 の本人作業

完了条件は「日本語ファイル名、名前の変更、削除、競合がすべて期待どおりに動く」。
Mac の `_test-vault` と、Windows に作るテスト用 Vault の 2 台で確かめる。
**Windows の普段の Vault にはプラグインを入れない。**

## 1. Mac で新しい版を Drive へ送る

1. `npm run dev` を動かしたまま、`_test-vault` を開いて `Cmd+R` で再読み込みする。
2. ステータスバーが「Drive: 待機中」になるまで待つ。起動時に自動で同期する。
3. 「確認待ち」と出たら **同期を実行** を実行し、内容を確かめて「実行」を押す。

`_test-vault-2` は使い終わった。Obsidian で開かなければ何も起きない。

## 2. Windows にテスト用 Vault を作る

1. Windows の Obsidian で左下の Vault 名から **Vault を管理** →「**新しい Vault を作成**」と進む。
2. 名前は **`_test-vault`**、場所は `D:\` の下に新しく作ったフォルダにする（例: `D:\obsidian-test`）。OneDrive の中には作らない。
   Drive のフォルダは Vault 名で決まるので、名前を変えると別の Vault になる。
3. 設定の「コミュニティプラグイン」で制限モードをオフにする。「インストール済みプラグイン」の横のフォルダのアイコンで `plugins` フォルダを開く。
4. `plugins` の中に `gdrive-vault-sync` フォルダを作る。
5. ブラウザで Google Drive を開き、`Obsidian/_test-vault/.obsidian/plugins/gdrive-vault-sync/` から `main.js` と `manifest.json` をダウンロードして、4 のフォルダへ入れる。
6. Obsidian の「インストール済みプラグイン」を更新し、**GDrive Vault Sync** を有効にする。
7. 設定でクライアント ID とシークレットを入れて、ログインする。ブラウザは Windows 側で開く。
8. `Ctrl+P` で **同期を実行** を選び、確認画面で「実行」を押す。
9. **端末と Drive を照合** を実行する。すべて 0 なら接続は完了。

`.obsidian` の中に競合コピーができるのは想定どおり（`spec-questions.md` Q12）。

## 3. 動きを確かめる

自動で同期するので、操作の後は 1 分ほど待つ。急ぐときは **同期を実行** を使う。

確認用のノートは `_test-vault/動作確認/` に用意してあり、Mac の同期で Windows にも届く。

| 確認 | ノート | 操作 | 期待する結果 |
|---|---|---|---|
| 日本語ファイル名 | `濁点ガギグ パピプ テスト`、`半角 と 全角　スペース`、`Finderで作った名前ガギグ` | 見るだけ | Windows に同じ名前で届き、文字化けせずに開ける |
| 名前の変更 | `名前を変えるノート` | Windows で「名前を変えた後のノート」に変える | Mac に新しい名前で届き、古い名前のノートは `.trash/` へ移る |
| 削除 | `削除するノート` | Mac で削除する | Windows の `.trash/` へ移り、Drive ではごみ箱へ移る |
| 競合 | `競合するノート` | Windows で **試行モード** をオンにして編集する。Mac でも別の内容に編集し、同期を待つ。Windows の試行モードをオフにする | Windows に Mac の内容が正式名で入り、Windows の内容は `名前 (conflict … Windows).md` に残る。ステータスバーに競合の件数が出る |
| 外からの編集 | `外から編集するノート` | Claude Code に編集を頼む | Windows に編集が届く |

最後に両方の端末で **端末と Drive を照合** を実行する。すべて 0 なら完了。

## 4. つまずいたとき

- 自動で同期されないときは、左のリボンに同期のアイコン（円形の矢印）があるか見る。無ければ古い版が動いているので、`Cmd+R`（Windows は `Ctrl+R`）で再読み込みする。`main.js` がビルドや同期で新しくなっても、動いている Obsidian には再読み込みするまで反映されない。
- 止まったときはステータスバーと通知を見る。「確認待ち」なら **同期を実行** で内容を確かめる。
- 失敗したら **ログをコピー** でログを取り、内容を確かめる。ログは Vault に書かない。

# 段階 4 の本人作業

完了条件は「2 週間、データの欠落と意図しない競合がない」。
iPad と Galaxy はテスト用 Vault だけを使う。**普段の Vault にはプラグインを入れない。**

## 1. Release を作る

GitHub の Release に、BRAT が読むファイルを置く。

1. Mac で `npm run build` を実行する。リポジトリ直下に `main.js` ができる。
2. `https://github.com/TommyPrime/gdrive-vault-sync/releases/new` を開く。
3. タグと Release 名は、どちらも `manifest.json` の版（例: `0.1.0`）にする。先頭に `v` を付けない。
4. `main.js` と `manifest.json` を添付して公開する。`styles.css` は空なので添付しない（GitHub は空のファイルを受け付けない）。

## 2. モバイルに入れる（iPad と Galaxy で同じ）

1. Obsidian で新しい Vault を作る。名前は **`_test-vault`** にする。iCloud には保存しない。
2. 設定の「コミュニティプラグイン」で制限モードをオフにする。
3. **BRAT** を検索してインストールし、有効にする。
4. BRAT の設定で「Add beta plugin」を選び、`TommyPrime/gdrive-vault-sync` を追加する。
5. 「インストール済みプラグイン」で **GDrive Vault Sync** を有効にする。

## 3. 接続する

1. **先に試行モードをオンにする。** モバイルの GDrive Vault Sync の設定で切り替える。
2. Mac の設定で「モバイル用トークン」の **表示** を押す。
3. 文字列をモバイルへ移す。
   - **iPad:** カメラアプリは文字列だけの QR を読めない（「使用可能なデータが見つかりません」と出る）。Mac の文字列の欄で `Cmd+A` → `Cmd+C` を押し、ユニバーサルクリップボードで渡す。貼り付けた後は、Mac で別の文字をコピーしてクリップボードから消す。
   - **Galaxy:** カメラで QR を読み取り、表示された文字列をコピーする。
4. モバイルの設定の「モバイル用トークン」に貼り付けて **接続** を押す。
5. 端末名が「iPad」や「Android」なら、そのままでよい。

トークンは写真に残さず、チャットやメールに貼らない。漏れたら Google アカウントの「サードパーティ製のアプリとサービス」でアクセスを取り消す。

## 4. 1 週間目: 4 台の試行

Mac と Windows も試行モードをオンにする。どの端末も書き込まない。

- 毎日 1 度、モバイルで Obsidian を開き、設定の先頭の「同期の状態」がエラーでないことを見る。
- 通知が出たら内容を控える。**ログをコピー** で計画を確かめられる。

## 5. 2 週間目: 実際の同期

Mac、Windows、iPad、Galaxy の順に試行モードをオフにする。

1. Mac と Windows は 1 分待って、照合が 0 件になるのを確かめる。
2. モバイルは **同期を実行** を実行し、確認画面の内容を確かめて「実行」を押す。初回だけ確認が出る。
3. 4 台でノートを編集して使う。モバイルは開いている間だけ同期する。

`.obsidian` の中に競合コピーができるのは想定どおり（Q12）。ノートの競合コピーが身に覚えなくできたら、内容を控える。

最後に 4 台で **端末と Drive を照合** を実行する。すべて 0 で、欠けたノートが無ければ完了。
